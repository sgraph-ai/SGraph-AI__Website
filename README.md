# SGraph-AI Website

Source for [https://sgraph.ai](https://sgraph.ai) — the SGraph AI marketing website.

Pure static HTML/CSS/JS with no build step. Deployed to S3 + CloudFront via GitHub Actions.

---

## Repo layout

The repo root is kept minimal. Everything is namespaced into two folders:

```
README.md                      This file
LICENSE                        Apache 2.0
MIGRATION-REPORT.md            Audit trail of the extraction from SGraph-AI__App__Send
.gitignore                     Repo-wide ignores
.github/workflows/             CI pipelines (GitHub Actions discovers only this path)

sgraph_ai_website/             Website source — everything that ships to S3
  version                      Current release tag (auto-incremented on push to dev/main)
  index.html                   Root redirect
  404.html                     Not-found page
  robots.txt                   Search crawler rules
  sitemap.xml                  Generated by sgraph_ai_website__deploy/generate_sitemap.py
  en-gb/                       Locale source (master) — homepage, product, agents,
                               architecture, contact, early-access, pricing, payment
  i18n/                        17 locale translation JSON files
  _common/                     Shared assets at the site root (css, fonts, img, js)
  v0/v0.2/v0.2.0/              IFD versioned tree — overlaid onto latest/ in CI
  cloudfront/                  CloudFront function source (url-rewrite.js)

sgraph_ai_website__deploy/     Build/deploy tooling — never shipped to S3
  deploy_static_site.py        S3 sync + CloudFront invalidation
  generate_i18n_pages.py       Pre-render locale pages from en-gb/ + i18n/*.json
  generate_sitemap.py          Build sitemap.xml with hreflang alternates
  store_ci_artifacts.py        Upload CI git-diff/commit metadata to S3
  website__run-locally.sh      Local IFD overlay + http.server on port 10060
```

## Stack

- **HTML / CSS / JS** — no bundlers, no framework, no build step
- **Web Components (Shadow DOM)** — `sg-site-header` plus 10 homepage sections
- **IFD versioning** — versioned source folders under `sgraph_ai_website/v0/v0.2/v0.2.0/...`
  are overlaid into a `latest/` union on S3 (v0.2.0 base + any v0.2.1+ patches)
- **17 locales** — 16 real + Klingon (`tlh`). English (en-GB) is the master;
  others are pre-rendered by `sgraph_ai_website__deploy/generate_i18n_pages.py`
- **Hosting** — S3 + CloudFront across 3 environments (dev, main, prod)

## Local development

Python 3.12 is the only prerequisite. From the repo root:

```bash
bash sgraph_ai_website__deploy/website__run-locally.sh
```

The script replicates the CI IFD overlay locally under `.local-server-website/`
and serves it on port 10060:

- Home: `http://localhost:10060/`
- EN-GB: `http://localhost:10060/en-gb/`
- Pricing: `http://localhost:10060/en-gb/pricing/`
- Security: `http://localhost:10060/en-gb/security/`
- Vaults: `http://localhost:10060/en-gb/vaults/`
- How it Works: `http://localhost:10060/en-gb/how-it-works/`

## Versioning

`sgraph_ai_website/version` holds the current release tag. It is auto-incremented
on every push to `dev` and `main` by the OSBot `git__increment-tag` action,
mirroring the convention used by `SGraph-AI__App__Send`:

- Push to `dev`  →  `release_type: minor`  (e.g. `v0.0.1` → `v0.1.0`)
- Push to `main` →  `release_type: major`  (e.g. `v0.1.0` → `v1.0.0`)
- Manual `production` dispatch → no increment; deploys the current tag

## CI pipelines

Mirrors the SGraph-AI__App__Send pattern: one reusable base + per-branch dispatchers.

| Workflow | Trigger | Action |
|---|---|---|
| `ci-pipeline.yml` | `workflow_call` (reusable) | Increment tag → check AWS creds → deploy |
| `ci-pipeline__dev.yml` | Push to `dev` | Calls base with `target_deploy=dev`, `release_type=minor` |
| `ci-pipeline__main.yml` | Push to `main` | Calls base with `target_deploy=main`, `release_type=major` |
| `ci-pipeline__prod.yml` | Manual dispatch only | Calls base with `target_deploy=prod`, `should_increment_tag=false` |

Each pipeline runs `sgraph_ai_website__deploy/deploy_static_site.py`, which:

1. Validates HTML files
2. Pre-renders 16 non-English locales via `generate_i18n_pages.py`
3. Syncs `sgraph_ai_website/` to `s3://{bucket}/websites/sgraph-ai/{env}/releases/{version}/`
4. Overlays the release onto `s3://{bucket}/websites/sgraph-ai/{env}/latest/`
5. Invalidates CloudFront

### Cache policy

| File type        | max-age | Duration  |
|------------------|---------|-----------|
| HTML             | 300     | 5 minutes |
| CSS / JS / JSON  | 86400   | 1 day     |
| Images / fonts   | 604800  | 7 days    |

CloudFront cache is fully invalidated on every deploy.

### Required GitHub Actions secrets

Configure under **Settings → Secrets and variables → Actions**:

| Secret                  | Purpose                                 |
|-------------------------|-----------------------------------------|
| `AWS_ACCESS_KEY_ID`     | AWS credentials for S3 + CloudFront     |
| `AWS_SECRET_ACCESS_KEY` | AWS credentials for S3 + CloudFront     |
| `WEBSITE_S3_BUCKET`     | S3 bucket holding static assets         |
| `WEBSITE_CF_DIST`       | CloudFront distribution ID (prod)       |
| `WEBSITE_CF_DIST_MAIN`  | CloudFront distribution ID (main/stage) |

Required GitHub Environments: `dev`, `main`, `prod`.

## IFD versioning

Versioned source folders under `sgraph_ai_website/v0/v0.2/v0.2.0/...` are deployed
as an **overlay** on top of `latest/` in S3. Each patch version adds or overrides
files — files from previous versions persist unless explicitly removed. Rollback
means re-syncing an earlier release. Cleanup of stale files is a deliberate,
manual step (typically on major version bumps).

This is why both `sgraph_ai_website/_common/` AND
`sgraph_ai_website/v0/v0.2/v0.2.0/_common/` exist: the top-level `_common/` is the
live marketing-site root; the versioned `_common/` is the IFD archive replayed into
`latest/` by the deploy script.
